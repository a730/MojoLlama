CLI Issues

mojollama command not found

Ensure the package is installed in your active Python environment:

$ cd MojoLlama/src && pip install -e .
$ mojollama --version
mojollama v0.5.0

If using a virtual environment, activate it first:

$ source .venv/bin/activate  # or .\venv\Scripts\activate on Windows

ImportError: No module named 'mojollama'

Run from the src/ directory or use pip install -e . to install in development mode:

$ cd MojoLlama/src && pip install -e .

mojollama bench crashes or shows 0 tok/s

Causes: missing GGUF file, wrong path, or incompatible quantization.

$ mojollama bench -m /path/to/model.gguf
Error: model file not found

Solutions:

  • Check the file path — use absolute paths
  • Verify the file is a valid GGUF:
    head -c 4 model.gguf | xxd should show 46474755 ("GGUF")
  • Check quantization type — MXFP4 requires the MXFP4 engine path
Tip: Use mojollama info -m model.gguf to inspect a model's metadata, architecture, and tensor layout before running benchmarks.

mojollama serve fails to start

$ mojollama serve -m model.gguf -p 8080
Error: Address already in use

Another process is using port 8080. Either kill it or use a different port:

$ lsof -i :8080
$ kill -9 <PID>
# or use a different port:
$ mojollama serve -m model.gguf -p 8081

Chat UI can't connect to server

The chat.html page sends requests to a MojoLlama server via the OpenAI-compatible API.

  1. Make sure the server is running: mojollama serve -m model.gguf -p 8080
  2. Enter the server URL in the chat UI (default: http://localhost:8080)
  3. Click Connect — the status indicator turns green
  4. If connecting from a different machine, use the server's IP/hostname instead of localhost
  5. Check that the server port is not blocked by a firewall
CORS note: If accessing the chat UI from a different origin (e.g., GitHub Pages), the server must include CORS headers. Start the server with --cors-allow-origin "*" if needed.

Docker Issues

Container exits immediately

Check logs:

$ docker logs <container-name>
$ docker compose logs mojollama

Common causes:

  • No model specified — set MODEL env var or mount a GGUF file at /models/
  • Model file not found — check the path in MODEL env var
  • Out of memory — the model requires more RAM than available

Model auto-download fails

The entrypoint script downloads models from HuggingFace using HF_REPO and HF_FILE env vars.

$ docker run -e HF_REPO=QuantFactory/Meta-Llama-3-8B-GGUF \
  -e HF_FILE=Meta-Llama-3-8B.Q4_K_M.gguf \
  -e MODEL=/models/Meta-Llama-3-8B.Q4_K_M.gguf \
  ghcr.io/a730/mojollama:latest mojollama chat

If download fails:

  • Check internet connectivity from within the container:
    docker run --rm ghcr.io/a730/mojollama:latest curl -I https://huggingface.co
  • Some models require authentication — set HF_TOKEN env var for gated models
  • Verify the file name — HuggingFace file names are case-sensitive

Container runs but inference is very slow

Update these env vars:

  • OMP_NUM_THREADS — set to number of physical cores (not logical threads)
  • AUTO_TUNE=true — runs hardware auto-tune on first model load
$ docker run -e OMP_NUM_THREADS=16 -e AUTO_TUNE=true \
  -e MODEL=/models/model.gguf ghcr.io/a730/mojollama:latest mojollama chat
Tip: Auto-tune results are cached per model hash in /root/.cache/mojollama/ so subsequent runs use the optimal config.

GPU not used / CUDA not available

MojoLlama is a CPU-first engine. It does not use CUDA or GPU acceleration. If you need GPU inference, use llama.cpp with the --n-gpu-layers flag via the llama.cpp fallback profile.

Model Loading

"Unknown architecture" error

If MojoLlama doesn't recognize your model's architecture:

  • Check what architecture the model reports: mojollama info -m model.gguf | grep architecture
  • Supported: Llama, Mistral, Qwen2, Qwen3, GPT-OSS, DeepSeek V2/V3, DBRX, Mixtral, Gemma 4, ZAYA1, Falcon (dev), Phi-3/4 (dev)
  • For unsupported architectures, MojoLlama falls back to a generic forward pass — results may be incorrect

"Unsupported quantization" error

Supported quantization types:

TypeDescription
Q4_04-bit, no K-quant
Q4_K_M4-bit K-quant medium
Q5_K5-bit K-quant
Q6_K6-bit K-quant
Q8_08-bit
MXFP44-bit MXFP4 (expert weights)

Performance

Lower throughput than expected

ProblemFix
OMP_NUM_THREADS too lowSet to number of physical cores (e.g., 32 for Threadripper 3970X)
OMP_NUM_THREADS too highMore threads != faster. For small models (ZAYA1-8B, <10B), 1 thread is optimal
Slow first tokenFirst inference includes model load time. Subsequent tokens are faster
Small model on many threadsOpenMP overhead dominates. Reduce threads for models under 10B params
CPU throttlingCheck CPU temperature and power limits: watch -n1 "grep MHz /proc/cpuinfo"

NaN values in output

NaN indicates a computation error, typically in:

  • Attention — softmax overflow or underflow. Try non-zero attention mask or smaller model context
  • LayerNorm / RMSNorm — division by near-zero variance. MojoLlama clamps RMS sum to [-1000, 1000]
  • MXFP4 matmul — scale overflow in 4-bit twos-complement arithmetic
  • Unsupported architecture — model architecture may need a specialized forward pass

Docker Compose Reference

Available profiles for docker compose:

ProfileCommandDescription
mojollamadocker compose --profile mojollama upAPI server with default config
chatdocker compose --profile chat upInteractive chat session
benchdocker compose --profile bench upRun benchmarks on the model
quantizedocker compose --profile quantize upQuantize a model to GGUF
autotunedocker compose --profile autotune upHardware auto-tune sweep
llama-cppdocker compose --profile llama-cpp upFallback to llama.cpp for unsupported models

Key environment variables:

VariableDefaultDescription
MODEL/models/model.ggufPath to the GGUF model file
PORT8080Server port
OMP_NUM_THREADS32OpenMP threads for parallel computation
AUTO_TUNEtrueEnable hardware auto-tune on first load
HF_REPO—HuggingFace repo for auto-download (e.g., QuantFactory/Meta-Llama-3-8B-GGUF)
HF_FILE—GGUF filename in the HF repo
HF_TOKEN—HuggingFace token for gated models

Still stuck? Open a GitHub issue with your logs and hardware details.
