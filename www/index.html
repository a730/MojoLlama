MojoLlama

High‑concurrency LLM serving engine with native GGUF support and dynamic CPU/GPU offloading — built in Mojo on the MAX platform.

Python Backend C Q4_0 Kernel OpenAI API GGUF Mojo 🔥 Apache 2.0

⚡About MojoLlama

🧠

Native GGUF

Load any quantized GGUF model directly — no conversion or glue code needed. Drop‑in replacement for llama.cpp.

⚡

High Throughput

Powered by MAX's continuous batching, RadixAttention, and PagedAttention. Targets 82+ tok/s on dense models.

🔄

Hybrid Execution

Dynamic CPU / GPU / Intel Arc offloading. Auto‑detects hardware and offloads layers when beneficial.

🔌

OpenAI API

Drop‑in replacement for any client using /v1/chat/completions and /v1/completions.

🦀

Mojo SIMD Kernels

Native AVX2/AVX512/NEON kernels via Mojo — compiled to native code, outperforming Python baselines by 10–60×.

📦

Single Binary

No Python, no Docker. Distribute a statically linked executable powered by Mojo + MAX (future target).

🔌API Reference

MojoLlama speaks the OpenAI API. Point any OpenAI client at the server URL.

▶ GET /v1/models List loaded models 
curl http://localhost:8080/v1/models

{
  "object": "list",
  "data": [{
    "id": "Llama-3.2-1B-Instruct-Q4_0",
    "object": "model",
    "created": 1747500000,
    "owned_by": "mojollama"
  }]
}
▶ POST /v1/chat/completions Chat completion (multi‑turn) 
curl -X POST http://localhost:8080/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{
    "messages": [
      {"role": "system", "content": "You are a helpful assistant."},
      {"role": "user", "content": "What is Mojo?"}
    ],
    "max_tokens": 128,
    "temperature": 0.7
  }'
▶ POST /v1/completions Text completion (simple prompt) 
curl -X POST http://localhost:8080/v1/completions \
  -H "Content-Type: application/json" \
  -d '{
    "prompt": "Once upon a time,",
    "max_tokens": 64
  }'
▶ GET /health Health check 
curl http://localhost:8080/health

{"status": "ok"}
