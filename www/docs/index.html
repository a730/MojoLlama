Getting Started

Installation

Clone the repository and install with pip in development mode:

$ git clone https://github.com/a730/MojoLlama.git
$ cd MojoLlama/src && pip install -e .

Verify the installation:

$ mojollama --version
mojollama v0.5.0

Quick start

Download a GGUF model and run chat inference:

$ mojollama convert --hf meta-llama/Llama-3.2-1B --outtype q4_0
$ mojollama chat -m model.gguf

Or use an existing GGUF file:

$ mojollama chat -m /path/to/model.gguf

CLI overview

The mojollama command provides a unified interface for all operations:

$ mojollama
  chat       Interactive chat with a model
  serve      OpenAI-compatible API server
  bench      Run benchmarks (tok/s, latency)
  convert    HuggingFace → GGUF conversion
  quantize   Quantize models (Q4_0, Q8_0, etc.)
  autotune   Hardware auto-tuning sweep
  info       Display model metadata
  eval       Run evaluation benchmarks
  train      LoRA fine-tuning
  export     Export to safetensors, ONNX
  hub        HuggingFace Hub operations

CLI Reference

mojollama chat

Interactive chat session with a loaded model.

$ mojollama chat -m model.gguf
$ mojollama chat -m model.gguf --temp 0.8 --max-tokens 2048
FlagDefaultDescription
-m, --model—Path to GGUF model file (required)
--temp0.7Sampling temperature (0–2)
--max-tokens512Maximum generation tokens
--top-p0.9Top-p nucleus sampling
--repeat-penalty1.1Repeat penalty

mojollama serve

Start an OpenAI-compatible API server for concurrent requests.

$ mojollama serve -m model.gguf -p 8080
$ mojollama serve -m model.gguf -p 8080 --workers 4
✓ Server started on http://0.0.0.0:8080
FlagDefaultDescription
-p, --port8080Server port
--workers1Number of worker processes
--batch-size1Batch size for inference
--cors-allow-origin—CORS origin (use * for all)

mojollama bench

Measure throughput and compare against llama.cpp.

$ mojollama bench -m model.gguf
$ mojollama bench -m model.gguf --prompt-tokens 512 --gen-tokens 128
$ mojollama bench -m model.gguf --compare  # vs llama.cpp

mojollama convert

Convert a HuggingFace model to GGUF format.

$ mojollama convert --hf meta-llama/Llama-3.2-1B --outtype q4_0
$ mojollama convert --hf mistralai/Mistral-7B --outtype q4_k_m

mojollama quantize

Quantize an existing GGUF model to a different precision.

$ mojollama quantize -m model.gguf -t q4_k_m
$ mojollama quantize -m model.gguf -t q8_0 -o model-q8.gguf

mojollama autotune

Sweep hardware parameters to find optimal settings for your model:

$ mojollama autotune -m model.gguf
$ mojollama autotune -m model.gguf --quick
✓ Optimal: threads=32, batch=512, concurrency=10

mojollama info

Display model metadata, architecture, and tensor layout without running inference.

$ mojollama info -m model.gguf
  Architecture:    llama
  Parameters:      7.24B
  Quantization:    Q4_K_M
  Context length:  8192
  Tensors:         291

Docker Guide

Quick start

Pull the latest image and run with a model:

$ docker pull ghcr.io/a730/mojollama:latest
$ docker run -e MODEL=/models/model.gguf -v /path/to/model.gguf:/models/model.gguf \
  ghcr.io/a730/mojollama:latest mojollama chat

Model auto-download

The entrypoint script downloads models from HuggingFace on first run. Set HF_REPO and HF_FILE to auto-download:

$ docker run -e HF_REPO=QuantFactory/Meta-Llama-3-8B-GGUF \
  -e HF_FILE=Meta-Llama-3-8B.Q4_K_M.gguf \
  -e MODEL=/models/Meta-Llama-3-8B.Q4_K_M.gguf \
  ghcr.io/a730/mojollama:latest mojollama chat

Hardware auto-tune

Set AUTO_TUNE=true (default) to run a hardware sweep on first model load. Results are cached per-model hash in /root/.cache/mojollama/ so subsequent runs use the optimal config immediately.

Model tips

  • Small models (<10B): Use 1 thread — OpenMP overhead kills performance on small matrix multiplications (e.g., ZAYA1-8B optimal at 1 thread)
  • Large models (>10B): Use all physical cores (e.g., 32 threads on Threadripper 3970X)
  • MoE models: MojoLlama excels here — GPT-OSS reaches 2.26× llama.cpp throughput
  • Check architecture: Use mojollama info -m model.gguf to verify a model is recognized

Troubleshooting

CLI issues

mojollama command not found

Install the package in your active Python environment:

$ cd MojoLlama/src && pip install -e .
$ mojollama --version
mojollama v0.5.0
Tip: If using a virtual environment, activate it first: source .venv/bin/activate

ImportError: No module named 'mojollama'

Run from the src/ directory or reinstall with pip install -e .

Benchmark crashes or shows 0 tok/s

  • Verify the model file path is correct and accessible
  • Check it's a valid GGUF: head -c 4 model.gguf | xxd should show 46474755 ("GGUF")
  • MXFP4 models require the MXFP4 engine path

Server fails to start (address in use)

$ lsof -i :8080
$ kill -9 <PID>
$ mojollama serve -m model.gguf -p 8081  # use different port

Chat UI can't connect

  1. Ensure server is running: mojollama serve -m model.gguf -p 8080
  2. Open studio.html and enter the server URL in the connection bar
  3. Click Connect — status should turn green
Note: If using a browser from a different machine, use the server's IP/hostname. For cross-origin access, start the server with --cors-allow-origin "*".

Docker issues

Container exits immediately

Check the logs:

$ docker logs <container-name>
$ docker compose logs mojollama

Common causes:

  • No model specified — set MODEL env var or mount a GGUF at /models/
  • Model file not found — verify the path in MODEL
  • Out of memory — model requires more RAM than available

Model auto-download fails

  • Check internet: docker run --rm ghcr.io/a730/mojollama:latest curl -I https://huggingface.co
  • Gated models need HF_TOKEN env var set
  • File names are case-sensitive on HuggingFace

Performance issues

ProblemFix
OMP_NUM_THREADS too lowSet to number of physical cores (e.g., 32 for Threadripper 3970X)
OMP_NUM_THREADS too highFor models <10B, 1 thread is optimal (OpenMP overhead)
Slow first tokenFirst inference includes model load time. Subsequent tokens faster.
CPU throttlingMonitor: watch -n1 "grep MHz /proc/cpuinfo"
Low throughputRun mojollama autotune --quick for optimized config

Model loading

"Unknown architecture" error

Check what architecture the model reports:

$ mojollama info -m model.gguf | grep architecture

If unsupported, MojoLlama falls back to a generic forward pass — results may be incorrect. See the architecture table for supported list.

NaN values in output

NaN indicates a computation error. Common causes:

  • Attention softmax — overflow/underflow. Try smaller context or non-zero attention mask
  • RMSNorm — near-zero variance. MojoLlama clamps RMS sum to [-1000, 1000]
  • MXFP4 — scale overflow in 4-bit arithmetic
  • Unsupported architecture — needs a specialized forward pass

API Reference

OpenAI-compatible API

MojoLlama serves an OpenAI-compatible API at /v1/chat/completions, compatible with the OpenAI Python client, LangChain, and any OpenAI SDK.

Chat Completions

$ curl http://localhost:8080/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{"model":"default","messages":[{"role":"user","content":"Hello!"}]}'
{"id":"chat-...","choices":[{"index":0,"message":{"role":"assistant","content":"Hi there!"},"finish_reason":"stop"}],"usage":...}

Model listing

$ curl http://localhost:8080/v1/models
{"object":"list","data":[{"id":"default","object":"model","created":...,"owned_by":"mojollama"}]}
Note: The API supports streaming (stream: true), temperature, top_p, max_tokens, frequency_penalty, and presence_penalty parameters.
